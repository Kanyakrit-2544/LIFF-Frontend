# S11 — ฐาน legacy (mock) + การจับคู่ด้วย AI

## 21.1 เป้าหมาย

ต่อท่อให้ AI ตอบคำถามธุรกิจได้ เช่น "คอร์ส Inner ช่วง ม.ค.–มี.ค. มีคนซื้อกี่คน ยอดเท่าไร มาจากช่องทางไหน"
และ "คนนี้เป็นลูกค้าเก่าหรือใหม่" โดย AI **ไม่เห็น PII แม้แต่ขั้นตอนเดียว**

```
LIFF/LINE ─► line_crm_dev ─┬─► Google Sheet                (จบตรงนี้ ไม่ scrub)
   (plaintext)             └─► WF-D scrub ─► line_crm_ai.customers_scrubbed ─┐
                                                                             │
Inner.xlsx ─► profile (สถิติล้วน) ─► generator ─► line_crm_legacy ─► scrub ──┤
                                       (synthetic)                           │
Facebook Lead ─► inbound_events ─► line_crm_dev ──(ทางเดิม)─────────────────►┤
                                                                             ▼
                                        MATCH: hash join ก่อน → LLM เฉพาะเคสกำกวม
                                                          │
                                                  customer_links
                                                          ▼
                                    ANALYTICS (aggregation = ตัวเลข) ─► insights
                                                          ▼
                                            RESTORE ที่ app เท่านั้น ─► คนอ่าน
```

## 21.2 กฎที่เพิ่มจากงานนี้

**LLM ห้ามเป็นคนบอกตัวเลข** ตัวเลขทั้งหมดมาจาก aggregation ใน `packages/core` เท่านั้น
LLM ทำได้ 3 อย่าง: เสนอ mapping ชื่อคอร์ส (offline ครั้งเดียว มีคนรีวิว) · เสนอการจับคู่คนเฉพาะเคสที่ hash ไม่ช่วย · แปลงคำถามเป็นพารามิเตอร์ + เขียนสรุปจากตัวเลขที่ได้มา
เหตุผล: LLM นับเลขจากข้อมูลหมื่นแถวแล้วมั่วเงียบ ๆ ตรวจไม่เจอจนกว่าจะมีคนเอาไปใช้ผิด และขัดกฎข้อ 1 (business logic อยู่ใน core)

## 21.3 ทำไมฐาน legacy เป็น synthetic

`raw input/Inner.xlsx` เป็น PII ลูกค้าจริง 10,615 แถวที่ไม่ได้ผ่าน consent ของระบบนี้
งานพัฒนา/ทดสอบ/ส่งให้ LLM ไม่ต้องใช้ตัวจริง — ใช้ข้อมูลที่มี "การกระจายเหมือนกัน" ก็ทดสอบได้ครบ

ขั้นตอนจึงเป็น: ดึง **สถิติล้วน** ออกจากชีต → ปั้นข้อมูลใหม่ตามสถิตินั้น
`packages/core/src/legacy/profile.json` ถูก commit ลง repo จึงต้องไม่มี PII แม้แต่ตัวเดียว —
มี test บังคับไว้ (`legacyGenerate.test.ts`) ว่าไฟล์ต้องไม่มีเบอร์ อีเมล หรือชื่อคน

**ข้อจำกัดที่ต้องกำกับทุกคำตอบ**: ตัวเลขจากฐานนี้เป็นตัวเลขปลอม ทุก doc ติดธง `synthetic: true`
วันที่จะสลับเป็นของจริง เปลี่ยนแค่ชั้น source — โครง doc ปลายทางเป็นตัวเดียวกัน

## 21.4 โครงข้อมูล — ทำไมต้องแยก 3 collection

| collection | 1 doc คือ | ถืออะไร |
|---|---|---|
| `legacy_persons` | คน 1 คน (dedupe แล้ว) | ตัวตน + ยอดสะสม |
| `legacy_payments` | 1 แถวในชีต = 1 การชำระ | **เงิน** |
| `legacy_enrollments` | 1 คอร์สที่ติ๊กในแถวนั้น | **ที่นั่ง** |

หนึ่งแถวติ๊กได้หลายคอร์สแต่มียอดเงินก้อนเดียว (ของจริง 15% ของแถวติ๊ก ≥2 คอร์ส)
ถ้าเอายอดไปแปะที่ระดับคอร์ส ยอดขายจะเบิ้ล — วัดจากข้อมูลจำลองปี 2025 แล้ว **เกินจริง 14.5%**

```text
ยอดถูก (payments):    36,306,490
ยอดผิด (enrollments): 41,564,210   เกินจริง 14.5%
```

## 21.5 เซลล์คอร์สไม่ได้แปลว่า "ขายได้" เสมอ

เซลล์เก็บความหมายทางธุรกิจไว้ในข้อความ ไม่ใช่แค่เครื่องหมายติ๊ก

| ข้อความในเซลล์ | ความหมาย | นับเป็นที่นั่งขายได้ |
|---|---|---|
| `27-28 Jun` | ลงเรียนรอบนั้น | ✓ |
| `RL 30-31 Aug` | Relearn ใช้สิทธิ์เรียนซ้ำ | ✗ |
| `Free 17-18 Jan` | ได้ฟรี | ✗ |
| `เพิ่ม IN-6806-00164` | รายการปรับ อ้างสลิปอื่น | ✗ |
| `ย้ายเรียน Camp` | ย้ายคอร์ส | ✗ |
| `Wait` / `คืนเงิน` / `ค่าปรับ` | รอคิว / คืนเงิน / ค่าปรับ | ✗ |
| `หนังสือ` / `ห้องพัก` / `ผ้าคลุม` | สินค้า ไม่ใช่ที่นั่ง | ✗ |
| `17-18 Jan 26` | รอบข้ามปี — ปีคือ 2026 ไม่ใช่วันที่ | ✓ |

วัดกับป้ายจริงทั้งหมดของชีต 2025–2026: เซลล์ไม่ว่าง 2,267 ช่อง เป็นที่นั่งที่ขายได้จริง **1,854 (81.8%)**
ถ้านับทุกเซลล์ที่ไม่ว่างเป็นการขาย ตัวเลขจะเกินจริงทันที 22%

**PII ซ่อนอยู่ในเซลล์**: บางช่องเขียนว่า `13-14 Jun คุณ<ชื่อจริง> เรียนแทน`
`parseCourseCell` จึงติดธง `substitute` และตัดชื่อออกจาก `sessionLabel` ส่วน `raw` เก็บไว้ในฐาน legacy เท่านั้น ห้ามออกไปโดยไม่ scrub

## 21.6 พจนานุกรมคอร์ส

ทั้งไฟล์มีหัวคอลัมน์คอร์ส **42 แบบ** ที่จริงเป็นคอร์สเดียวกันหลายชื่อ (`Inner`/`Inner Makeover`, `MC Pro`/`MC Pro7`/`MC Pro#ุ6`)
`courses.ts` เป็นความจริงชุดเดียว — analytics ห้ามเทียบด้วยชื่อดิบ และห้ามให้ LLM แปลตอน query
ตอนนี้ครอบคลุมชีต 2025–2026 (7 หัวคอลัมน์ → 7 รหัส) เพิ่มปีเก่า = เพิ่มบรรทัดในตาราง หัวคอลัมน์ที่ไม่รู้จักคืน `null` และถูกรายงานใน `legacy_import_runs.unknownCourseHeaders` ไม่ใช่เดา

## 21.7 คำสั่ง

```bash
npm run legacy:profile                                   # ดึงสถิติจากชีตใหม่ (ต้องมี openpyxl)
npm run legacy:generate -- --uri "mongodb://localhost:27018/?directConnection=true" --db line_crm_legacy --drop
npm run legacy:generate -- --scale 0.1 --seed 42         # ชุดเล็กไว้ลองเร็ว ๆ
```

`--uri` อ่านจาก `LEGACY_MONGODB_URI` แล้วค่อย `MONGODB_URI` — `app_user` มีสิทธิ์เฉพาะ `line_crm_dev`
ถ้าจะลง Atlas ต้องสร้าง user ใหม่ที่ `readWrite` เฉพาะ `line_crm_legacy` ก่อน

## 21.9 ที่ยังไม่ได้ทำ

| ขั้น | งาน |
|---|---|
| M2 | scrub legacy → `line_crm_ai.legacy_persons_scrubbed` ด้วย `AI_HASH_PEPPER` ตัวเดิม (ต่างชุด = join ไม่ติด) |
| M3 | match engine: `phoneHash`/`emailHash` ตรง = auto · ไม่ตรง = LLM เสนอ → `needs_review` เสมอ |
| M4 | analytics + `insights` collection + ชั้นแปลงคำถามภาษาไทยเป็นพารามิเตอร์ |
| M5 | restore token → ค่าจริง ที่ app เท่านั้น |
| M6 | Facebook Lead Ads: `/api/webhook/facebook` + `X-Hub-Signature-256` → `inbound_events` ท่อเดียวกับ LINE ใส่ token แล้วรันได้เลย ไม่มี mock |
| — | ชีต 2019–2024: เพิ่ม `SheetLayout` + เติมพจนานุกรมคอร์ส ไม่ต้องแก้ logic |
