# S7 — ตรวจความปลอดภัยหน้า LIFF + logging

## 18.1 ที่ทดสอบและปลอดภัยอยู่แล้ว

ยิง payload โจมตีเข้าช่องกรอกจริงทุกแบบ **บล็อกหมด**

| ทดสอบ | ผล |
|---|---|
| `{"$ne": null}` ในช่องข้อความ | 400 |
| `{"$gt": ""}` | 400 |
| `{"$where": "1==1"}` | 400 |
| `{"$regex": ".*"}` | 400 |
| array แทน string | 400 |
| object ซ้อน | 400 |
| `formVersion` / `idempotencyKey` เป็น object | 400 |
| `answers` เป็น array / string | 400 |
| ยัด `customerStatus` / `_id` / `sheetSync` / `counters` / `consent` | 400 ทุกตัว |

**เหตุผลที่กันได้:** `buildZodFromSchema()` สร้าง validator จาก schema แล้วปิดท้ายด้วย `.strict()`
ทุกช่องมีชนิดชัดเจน — ส่ง object เข้าช่อง `text` = ไม่ผ่านตั้งแต่ parse และ field ที่ไม่มีใน schema ทำให้ทั้งก้อนถูกปฏิเสธ
ค่าที่ผ่านเข้าไปถึง MongoDB จึงเป็น string/number/boolean เสมอ ไม่มีทางกลายเป็น operator

**การลบข้อมูล:** ไม่มี endpoint ไหนที่ LIFF เรียกแล้วลบอะไรได้เลย — `/liff/*` มีแค่อ่านกับเขียนของตัวเอง

## 18.2 🔴 ช่องโหว่ที่เจอ: ดูดข้อมูลลูกค้าคนอื่นด้วยเบอร์โทร

### วิธีโจมตี

1. ผู้โจมตีแอด LINE ปกติ → ได้บัญชีของตัวเองที่มี identity verified
2. เปิด LIFF กรอกฟอร์ม แต่ใส่ **เบอร์ของลูกค้าคนอื่น**
3. ระบบ auto-merge (D3) → บัญชีผู้โจมตีชนะเพราะมี identity verified ส่วนลูกค้าเก่าที่ import มาไม่มี
4. merge เติมข้อมูลของเหยื่อเข้าบัญชีผู้โจมตี
5. เปิดหน้า LIFF อีกครั้ง → `/api/liff/bootstrap` คืนข้อมูลเหยื่อออกมา

ผลจริงที่ทดสอบได้:
```
ชื่อเล่น : "เหยื่อ"              ← ไม่เคยกรอก
อีเมล    : "victim@example.com"  ← ไม่เคยกรอก
ปีเกิด   : "2530"                ← ไม่เคยกรอก
```

### ต้นเหตุ

D3 กำหนดให้ **auto-merge เมื่อ `phoneHash` ตรง** แต่เบอร์ที่พิมพ์ในฟอร์มเป็น **การอ้างที่ยังไม่ได้ตรวจสอบ**
ใครก็พิมพ์เบอร์ของใครก็ได้ — การเอาการอ้างที่ไม่ได้ตรวจสอบมาผูกสองบัญชีเข้าด้วยกัน คือการยึดบัญชีโดยออกแบบ

ตอนถามเรื่องนี้ครั้งแรก (docs/00 RISK-1) ผมเสนอทางเลือกว่าจะ auto-merge หรือให้คนกดยืนยัน
แต่**ไม่ได้อธิบายว่าผลข้างเคียงคือข้อมูลรั่ว** — เป็นความผิดพลาดของผมในการนำเสนอ

### วิธีแก้ที่ใช้

**ไม่ merge อัตโนมัติอีกต่อไป** — เบอร์ตรงกับลูกค้าคนอื่นเมื่อไหร่:
- บันทึกข้อมูลลงบัญชีของผู้กรอกตามปกติ
- ตั้ง `customers.pendingMerge = { candidateId, reason: "phone_match", at }`
- เขียน `audit_logs` action `customer.merge_pending`
- **ไม่แตะบัญชีอีกฝ่ายเลย** และไม่ดูดข้อมูลข้ามมา

`mergeCustomers()` ยังอยู่ครบ — ใช้ได้เมื่อเจ้าหน้าที่ตรวจแล้วสั่งรวม หรือเมื่อมีการยืนยันเบอร์ (OTP) ในอนาคต

**ต้นทุนที่ต้องยอมรับ:** ลูกค้าเก่าที่แอด LINE ใหม่จะไม่ถูกรวมอัตโนมัติ ต้องมีคนกดรวม
แลกกับการที่คนรู้เบอร์ลูกค้าไม่สามารถดึงข้อมูลออกไปได้

> ถ้ายืนยันว่าอยากได้ auto-merge กลับมาโดยรับความเสี่ยงนี้ บอกได้ ผมเปิดคืนให้พร้อมบันทึกไว้ว่าเป็นการตัดสินใจที่รู้ผลแล้ว

## 18.3 ช่องโหว่อื่นที่ปิดไปด้วย

| ปัญหา | เดิม | แก้เป็น |
|---|---|---|
| `clientMeta` ไม่ผ่าน validation | ส่ง 2MB → เก็บลง DB ทั้งก้อน | `capMeta()` — ไม่เกิน 2KB, ค่าละไม่เกิน 256 ตัวอักษร, key ยาวเกิน 40 ตัดทิ้ง |
| ไม่มี rate limit | ยิง 12 ครั้งรวด ผ่านหมด | 5 ครั้ง/นาที/ลูกค้า → เกินได้ 429 · `/liff/session` 20 ครั้ง/นาที/IP |
| `formId` ชนิดผิด | ใช้ค่า default เงียบ ๆ | 400 |
| บัญชีที่ถูก merge ไปแล้ว | bootstrap คืน tombstone ที่ว่างเปล่า | ตาม `mergedInto` ไปหาตัวจริง (สูงสุด 5 ชั้น) |

`rate_limits` เป็น collection ใหม่ มี TTL index ลบตัวเองอัตโนมัติ — ใช้ Mongo เพราะยังไม่มี Redis
ถ้าโตจนเป็นคอขวดให้ย้ายไป Upstash โดยแก้แค่ `security/rateLimit.ts`

**DB ล่ม → rate limit ปล่อยผ่าน** ตั้งใจให้เป็นแบบนี้ ลูกค้าจริงต้องส่งฟอร์มได้แม้ระบบนับมีปัญหา

## 18.4 Log ข้อมูลจาก LIFF บน Vercel

เก็บได้ แต่ **ไม่เก็บค่าที่ลูกค้ากรอกจริง** — log บน Vercel ถูกก็อปวาง ส่งต่อ และเก็บไว้บนเครื่องคนอื่นได้ง่าย
ถ้าเบอร์กับอีเมลอยู่ในนั้น = PII รั่วออกนอกระบบที่เราคุมได้ (docs/06 §6.11)

บันทึกเป็น **ชื่อช่อง + กรอกหรือไม่ + ยาวเท่าไร** แทน

```json
{"level":"info","msg":"รับข้อมูลจากฟอร์ม LIFF","requestId":"job_01M10JPP9B…",
 "revision":1,"duplicate":false,"pendingMerge":false,"formVersion":"v1",
 "fields":{"fullNameTh":"กรอก 10 ตัวอักษร","phone":"กรอก 10 ตัวอักษร","consentDataProcessing":"ติ๊ก"},
 "filled":3,"total":3}
```

ตอบได้ว่า: ใครส่งเมื่อไหร่ · ครบกี่ช่อง · ช่องไหนคนข้าม · เป็น revision ที่เท่าไร · ซ้ำหรือไม่ · ติดธง merge หรือไม่
ตอบไม่ได้ว่า: เบอร์อะไร ชื่ออะไร — ดูใน MongoDB แทน

**ดูบน Vercel:** dashboard → project → **Logs** → กรอง `รับข้อมูลจากฟอร์ม LIFF`
หรือ `npx vercel logs <deployment-url>`

`error` log ก็ redact อัตโนมัติอยู่แล้ว — `logger.ts` ลบเบอร์/อีเมล/JWT/เลขบัตรออกทุกครั้งที่เขียน

## 18.6 ที่ยังไม่ได้ทำ

- **หน้าให้เจ้าหน้าที่ดู `pendingMerge` แล้วกดรวม** — ตอนนี้ต้องดูใน MongoDB เอง ควรทำตอนมี admin UI
- **ยืนยันเบอร์ด้วย OTP** — ถ้ามีแล้วจะ auto-merge ได้อย่างปลอดภัย
- **CSP header** บนหน้า LIFF — ยังไม่ตั้ง
