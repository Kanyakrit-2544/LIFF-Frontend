# คู่มือทดสอบหน้า Admin ในเครื่อง

คู่มือนี้ใช้ประวัติซื้อจริงจาก `raw input/Inner.xlsx` เฉพาะใน Mongo local ร่วมกับข้อมูลจำลองสำหรับคิวอื่น ไม่ต้อง deploy และไม่ต้องล็อกอิน Google จริง

> ข้อมูล legacy มีชื่อ เบอร์ และอีเมลจริง ห้ามส่งออกจากเครื่อง ห้ามนำฐาน local ไปอัปโหลด และห้าม commit ไฟล์จาก `raw input/`

## 1. เตรียมค่า local โดยไม่ทำค่าจริงหาย

ไฟล์ `apps/web/.env.local` ปัจจุบันอาจมีค่า Atlas และ secret จริง ให้สำรองก่อนทุกครั้ง:

```bash
cp apps/web/.env.local apps/web/.env.local.atlas-backup
cp apps/web/.env.local.example apps/web/.env.local
```

ไฟล์ตัวอย่างใช้ Mongo ที่ `localhost:27018` ทุก URI พร้อม `directConnection=true` แล้ว

## 2. เปิดฐานข้อมูลและใส่ข้อมูลทดลอง

รันจากโฟลเดอร์หลักของโปรเจกต์:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-legacy.txt
npm run db:test:up
npm run seed:local -- --drop --legacy-limit 200
```

สองคำสั่งแรกเตรียมตัวอ่าน Excel และทำครั้งแรกครั้งเดียว รอบถัดไปเริ่มที่ `npm run db:test:up` ได้เลย

ถ้าแจ้งว่าชื่อ `line-crm-mongo` ถูกใช้แล้ว แปลว่าฐาน local เปิดอยู่ ให้ข้ามคำสั่งแรกและรัน seed ต่อได้

ท้ายคำสั่ง seed ต้องเห็นสรุปประมาณนี้:

- ลูกค้าซ้ำอย่างน้อย 3 รายการ
- Legacy persons จริงจากไฟล์ตามจำนวนแถวที่กำหนด
- Customers ที่จับคู่กับ legacy ได้ประมาณ 20 คน
- ลิงก์มีทั้ง auto, needs_review และ confirmed อย่างน้อย 3
- Partner 4 รายการ โดยมี `pending_identity` 2 และ `quarantined` 2
- ลูกค้า 40 คน และ erased 2 คน
- Analytics ครบ 6/6 metric

`--legacy-limit` ปรับจำนวนแถวจริงที่อ่านได้ ค่าเริ่มต้นคือ 200 แถว รัน `npm run seed:local` ซ้ำได้ จำนวนข้อมูลจะไม่เพิ่ม และใช้ `--drop` เมื่อต้องการเริ่มชุดทดสอบใหม่ทั้งหมด โดยไม่แตะข้อมูลอื่นในเครื่อง

## 3. เปิดเว็บและเข้าสู่ระบบ

```bash
npm run dev --workspace @line-crm/web
```

เปิด [http://localhost:3000/admin/login](http://localhost:3000/admin/login) แล้วกด **เข้าสู่ระบบ (dev)** ระบบจะพาไปหน้า `/admin/review`

## 4. เช็กลิสต์หน้า Review

### ลูกค้าซ้ำ

- เปิดแท็บ **ลูกค้าซ้ำ** ต้องเห็นอย่างน้อย 3 คู่
- กด **ยืนยัน** 1 คู่ รายการนั้นต้องหายจากคิวและลูกค้าถูกรวมกัน
- กด **ปฏิเสธ** อีก 1 คู่ รายการต้องหายและระบบต้องจำการปฏิเสธถาวร

### ประวัติเก่าและกฎ D23

- เปิดแท็บ **ประวัติเก่า** แล้วกด **ดูโปรไฟล์ลูกค้า** ของรายการที่รอตรวจ
- ก่อนยืนยัน ต้องเห็นคำเตือนว่ามีประวัติรอยืนยัน และยังไม่เห็นรายการซื้อ legacy
- กลับมาแท็บเดิม กด **ยืนยัน** แล้วเปิดโปรไฟล์คนเดิมอีกครั้ง
- หลังยืนยัน ประวัติซื้อเดิม ยอดชำระ และคอร์สจึงจะปรากฏ
- โปรไฟล์ที่ seed ยืนยันไว้แล้วสำหรับดูประวัติจริงทันทีคือ `/admin/customer/cus_LOCAL_001`, `/admin/customer/cus_LOCAL_002` และ `/admin/customer/cus_LOCAL_003`

### Partner

- เปิดแท็บ **Partner** ต้องเห็น `pending_identity` 2 รายการ และ `quarantined` 2 รายการ
- เลือกลูกค้าที่ระบบเสนอให้รายการ `pending_identity` แล้วกด **ยืนยันลูกค้า**
- ใส่เหตุผลในรายการ `quarantined` แล้วกด **ปฏิเสธรายการ**
- ทั้งสองรายการต้องหายจากคิวหลังบันทึกสำเร็จ

## 5. เช็กลิสต์โปรไฟล์ลูกค้า

- เปิด `/admin/customer/cus_LOCAL_001` ตรวจว่ายอดรวม จำนวนการชำระ ที่นั่ง และรายชื่อคอร์สสอดคล้องกับไทม์ไลน์
- การชำระ `33,900` บาทมี 3 คอร์ส ยอดรวมต้องนับเงินก้อนนี้ครั้งเดียว ไม่ใช่สามครั้ง
- เปิด `/admin/customer/cus_LOCAL_039` และ `/admin/customer/cus_LOCAL_040`
- ลูกค้า erased ต้องขึ้นคำเตือนและไม่แสดงชื่อ เบอร์ หรืออีเมล

## 6. เช็กลิสต์ Analytics

- เปิด [http://localhost:3000/admin/analytics](http://localhost:3000/admin/analytics)
- เลือกดูทีละ metric: ยอดขาย, ที่นั่ง, จำนวนลูกค้า, ลูกค้าใหม่/เก่า, ช่องทางที่มา และความสนใจจาก AI
- ทั้ง 6 metric ต้องมีตัวเลขหรือแถวผลลัพธ์
- ผลที่รวมข้อมูล Partner จำลองต้องขึ้นแถบเตือนสีแดง และความสนใจจาก AI ต้องขึ้นแถบเตือนค่าประเมินสีเหลือง

## 7. จบการทดสอบ

หยุดเว็บด้วย `Ctrl+C` แล้วคืนค่า Atlas เดิม:

```bash
cp apps/web/.env.local.atlas-backup apps/web/.env.local
npm run db:test:down
```

อย่านำไฟล์ `.env.local` หรือไฟล์สำรองที่มี secret ขึ้น Git
